## 学习推演与实践方法

本节是面向自己项目的分析和练习，不代表作者已经实现或验证这些方案。

### 用可观察行为检验玩法

为一个原型写下三个问题：玩家眼下想完成什么？需要作出什么选择？结果怎样改变下一次行动？如果回答只有“继续移动，直到时间结束”，就需要进一步验证玩家在过程中是否获得足够的判断空间。

可以组织一次短试玩，让观察者记录玩家主动采取的行动，而不只记录游玩时长。例如：是否等待同伴、是否为资源偏离路线、是否为了完成共同目标承担风险。试玩后询问“刚才哪一次决定最有意思”，比单问“好不好玩”更容易得到具体反馈。

多人功能的价值也需要单独验证：如果加入第二名玩家后，双方仍然互不影响，合作的设计空间可能尚未打开。可以先做一个依赖配合的小目标，观察它是否自然产生交流，再决定扩充多少内容。

### 拆开成员资格 连接状态与业务状态

排查联机故障时，可以建立三份独立记录：

| 要回答的问题 | 建议记录 |
| --- | --- |
| 谁属于这场会话 | 玩家 ID、加入和离开记录、会话标识 |
| 当前能否通信 | 建链阶段、最近收包时间、重连次数 |
| 游戏规则进展到哪里 | 准备状态、状态版本、开始条件、当前阶段 |

让日志携带同一个会话标识和玩家 ID，才能把一次 Ready 操作从发送、接收、解析一直追到界面更新。仅有 ping 或收包计数，很难定位故障发生在哪一层。

对于重要操作，还应考虑重试的结果：同一条开始指令收到两次时，是否会重复加载场景？一条旧的准备状态晚到时，是否会覆盖新状态？可以用操作编号或状态版本设计实验，明确重复和过期消息的处理方式。

### 理解 C# 值类型复制的实际影响

C# 默认按值传参：传入结构体时复制其值，`ref` 允许被调用方法修改原变量。结构体内若保存数组引用，复制结构体后仍可能引用同一个数组；结构体自己的计数或游标字段则各有一份。[Microsoft C# 参数文档](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/method-parameters)

因此，分析 writer 一类对象时，要同时检查“缓冲区内容”和“已写入长度”。共享缓冲区里出现字节，并不能单独证明最终导出的数据包含这些字节。原文未展示完整 writer 实现，具体应检查哪些字段，要以实际代码为准。

建议做一个小练习：创建含缓冲区引用与长度字段的结构体，分别按值和按引用调用写入方法；观察调用者的长度与缓冲区如何变化。再让读取器还原一个带布尔值、字符串和数值的消息，验证字段值一致、读取边界正确。练习目标是理解数据流，而不是只验证发送函数没有抛异常。

### 为坐标转换建立不变量

把“换原点前后，车辆在持久世界中的位置不变”作为检查目标。以下数值为自行设计的练习：

```text
迁移前：局部位置 5200，累计偏移 0，逻辑位置 5200
迁移后：局部位置 200，累计偏移 5000，逻辑位置 5200
```

进一步让两个客户端在不同帧迁移原点，检查相同逻辑位置是否仍能正确转换为各自的局部位置。这个实验能揭露把某台机器的局部坐标直接当成共享坐标的问题。

视觉检查还应覆盖保存历史位置的对象：例如摄像机平滑缓存、粒子或轨迹。位置当前值正确，不意味着历史缓存已经正确处理。

### 为确定性生成检查隐藏输入

可以把生成接口当作一份约定：相同输入应产生相同结果。自检时重点寻找隐藏输入，例如系统时间、其他系统消耗过的随机数、对象遍历顺序、资源版本差异。

一个有价值的实验是让客户端 A 按顺序生成分段，让客户端 B 以乱序生成同一批分段，再比较每段的内容摘要。如果生成结果依赖之前生成过什么，就需要重新审视随机源和状态管理。

还要区分静态生成结果与玩家造成的变化。场景初始内容可重建，并不意味着“某个补给已被取走”也会自动保持一致。后者需要单独决定由谁记录，以及晚加入玩家怎样恢复。

### 设计能够证明完成的验收

验收用例应描述玩家经历和预期结果，而不只列功能名称。可从下面几条开始：

- 两台机器从建房、准备到完成一局，双方看到一致的阶段结果。
- 玩家短暂断线后恢复，成员身份和界面状态符合预先定义的规则。
- 重复发送同一重要操作，不会重复产生业务副作用。
- 两端采用不同生成顺序、不同原点迁移时机，仍看到一致的世界关系。
- 发布前确认正在验证的构建与待发布构建一致，保留版本标识。

每项结果记录“通过、失败、未执行”，并保留复现步骤。这样才能据此判断下一步应修故障、补验证，还是继续制作内容。

## 复习问题

1. 访问、购买、实际游玩和复玩分别需要什么证据？
2. 一次短试玩中，哪些行为能说明玩家正在作出有意义的选择？
3. 收到数据包后，还需要经过哪些步骤，界面才应显示准备成功？
4. 结构体中的引用字段与普通数值字段，复制后有什么区别？
5. 两台机器的局部原点不同，如何比较同一对象的位置？
6. 哪些内容可以重建，哪些状态必须记录玩家已经造成的变化？
7. 什么验收结果足以支持“这个功能可以交给玩家使用”？
