# Hermes介绍、部署与我的使用方式 - 口播稿

哈喽大家好，欢迎来到 GameBoy，我是小新。

最近这段时间，我一直在折腾一个东西，叫 Hermes Agent。

如果你平时有关注 AI 工具，可能会听过很多类似的名字，比如 Claude Code、Codex、各种 AI Agent、各种自动化助手。

但 Hermes 给我的感觉比较特殊。

因为它不是一个单纯的聊天机器人，也不是一个只能在网页里回答问题的 AI。

更准确一点说，它像是一个真正装在我电脑里的 AI 助手。

它能读我本地的文件，能操作终端，能写代码，能改文档，能定时执行任务，还能通过 Telegram 直接和我对话。

也就是说，它不是我打开网页以后问一句、答一句的工具。

而是一个长期运行在我电脑里的工作系统。

所以今天这个视频，我想结合我自己的部署过程和现在的使用方式，跟大家聊一下 Hermes 到底是什么，它怎么部署，以及我现在是怎么把它用到内容创作、邮件处理、社交媒体运营，还有项目开发里的。

如果你也在研究 AI Agent，或者你想让 AI 不只是陪你聊天，而是真的接入你的工作流，那这个视频应该会有点帮助。

好的，废话少说，我们直接开始。

## 第一，Hermes 到底是什么

首先我们先讲清楚，Hermes 到底是什么。

Hermes Agent 是 Nous Research 做的一个开源 AI Agent 框架。

你可以把它理解成一个可以在本地运行的 AI 助手系统。

它最核心的特点不是“能聊天”，而是“能使用工具”。

比如它可以使用终端，可以读写文件，可以搜索网页，可以操作浏览器，可以分析图片，可以生成图片，可以运行 Python 脚本，可以管理定时任务，也可以通过 Telegram、Discord、Slack 这类平台跟你交互。

这就意味着什么？

意味着它不是停留在“给你建议”的层面。

你问普通 AI：帮我整理一下这个文件。

它可能会告诉你怎么整理。

但 Hermes 是可以真的去打开这个文件，读里面的内容，然后帮你改好，再保存回去。

你问普通 AI：每天帮我看一下未读邮件。

它可能会给你一个自动化思路。

但 Hermes 可以真的每天定时跑一次，把未读邮件整理成摘要，再发到我的 Telegram 里。

这就是我觉得 Hermes 最重要的区别。

它不是一个回答问题的工具，而是一个可以进入你真实工作环境里的执行者。

当然，这里也要说清楚，它不是魔法。

它依然会犯错，依然需要你给它边界，依然需要你告诉它什么可以做、什么不能做。

但它的上限，比普通聊天机器人要高很多。

因为它能接触到真实的文件、真实的命令、真实的工作流。

## 第二，Hermes 的部署思路

然后说一下部署。

Hermes 的部署方式其实不算特别复杂，但它确实不是那种点开网页就能用的产品。

它更像是一个开发者工具。

你需要把它装到自己的电脑上，然后配置模型、配置工具权限、配置消息平台、配置定时任务。

我现在这台电脑上，是把 Hermes 装在本地 Linux 环境里。

它的主目录在 `.hermes` 下面，里面有配置文件、环境变量、技能、记忆、会话记录，还有 Hermes 自己的源码目录。

最基础的安装方式，大概就是用官方安装脚本：

```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

安装完之后，可以通过：

```bash
hermes setup
```

进入它的配置向导。

这个向导里面会让你配置几个关键东西。

第一个是模型。

Hermes 本身不绑定某一个模型，它支持 OpenRouter、OpenAI、Anthropic、Gemini、DeepSeek、本地模型，还有很多其它 provider。

也就是说，你可以根据自己的预算和需求去切换模型。

第二个是工具权限。

Hermes 的工具是可以单独开关的。

比如终端、文件读写、浏览器、网页搜索、图片分析、定时任务、消息发送、记忆系统、子任务代理等等。

这点我觉得非常重要。

因为 AI Agent 最大的问题不是它不够聪明，而是它一旦能操作你的电脑，你就必须非常清楚它能碰什么，不能碰什么。

所以 Hermes 的工具集是可以分层配置的。

你可以只让它读文件，也可以让它写文件；可以让它跑终端，也可以限制它不能做一些高风险命令。

第三个是 Gateway，也就是消息平台。

我现在最常用的是 Telegram。

Hermes 在我的电脑上以一个后台服务的方式运行，Telegram 消息发过来以后，它就能收到，然后调用本地工具执行任务，最后再把结果发回 Telegram。

这件事对使用体验影响特别大。

因为我不需要每次都打开终端。

我可以直接像现在这样，在手机上给它发消息。

比如：

帮我在 Obsidian 里写一个稿子。

帮我查一下定时任务。

帮我整理一下 X 的互动候选。

帮我看一下某个项目目录。

它都可以直接在电脑上执行。

第四个是 Cron，也就是定时任务。

这也是 Hermes 很有用的地方。

因为很多 AI 工具都是被动的，你问它，它才回答。

但 Hermes 可以主动定时运行。

比如每天固定时间检查邮件，固定时间搜索 X 上值得互动的内容，然后自动整理成消息发给我。

这就让 AI 从“临时助手”变成了“长期值班的人”。

## 第三，我现在实际启用了哪些能力

那我现在到底把 Hermes 用在什么地方？

这里我就不讲概念了，直接说我当前电脑里已经跑起来的几个功能。

第一，是 Telegram 远程助手。

这是我现在最常用的入口。

Hermes 的 Gateway 服务一直在后台运行，所以我可以直接在 Telegram 里给它发消息。

这意味着什么？

意味着只要我的电脑在线，我在手机上就能调动电脑里的 AI。

它可以帮我读 Obsidian 笔记，写稿子，查文件，跑命令，生成内容，甚至检查它自己的配置状态。

这也是我觉得 Hermes 最有想象力的地方。

因为 AI 不再被锁在某个网页窗口里。

它变成了一个随时可以通过聊天窗口调用的本地操作系统助手。

第二，是 Obsidian 内容创作。

我的很多内容选题、脚本、游戏开发笔记，都放在 Obsidian 里。

比如独立游戏开发、Steam Demo、X 账号运营、YouTube 内容方向，这些东西都有对应的笔记。

Hermes 可以直接读取我的 Obsidian vault，然后按照我的写作习惯生成稿子。

像现在这篇稿子，其实就是我直接在 Telegram 里让 Hermes 写到 Obsidian 里的。

它不需要我复制粘贴，也不需要我把旧稿子全部发给它。

它可以自己去读我的 `content create` 文件夹，参考我最近写过的口播稿结构，然后生成一篇新的稿件。

这个工作流对内容创作很有帮助。

因为以前写稿子最麻烦的不是打字，而是你要把素材、风格、结构重新组织一遍。

现在 Hermes 可以先把初稿搭起来。

我再去做判断、修改、补充个人表达。

这就像把最痛苦的第一版草稿交给了一个助手。

第三，是 Gmail 未读邮件摘要。

我现在有一个定时任务，会在每天 10 点、14 点、17 点检查 Gmail 未读邮件。

它会把最近的未读邮件整理成中文摘要，然后发到 Telegram。

这件事听起来很简单，但实际用起来很舒服。

因为邮箱这个东西很容易变成信息黑洞。

你不看，可能会漏重要信息；你一直看，又会被各种无关邮件打断。

所以我现在的处理方式是，让 Hermes 定时帮我扫一遍。

真正重要的邮件，它会提醒我。

不重要的，我就不用一直打开邮箱。

这就是 AI Agent 很适合做的事情：

不是替你做重大决策，而是帮你守住那些重复、琐碎、但又不能完全忽略的信息入口。

第四，是 X/Twitter 运营辅助。

我现在的 X 账号主要围绕独立游戏开发、AI 工具、游戏制作经验来做内容。

Hermes 里有一个定时任务，会在每天固定时间搜索 X 上和这些方向相关的内容，然后筛选出比较适合互动的候选。

注意，这里它不是直接帮我发帖，也不是自动回复别人。

它只做只读搜索和草稿生成。

也就是说，它会告诉我：

今天有哪些帖子可能值得回复。

为什么这个帖子值得互动。

我可以怎么回复。

但最后发不发，怎么改，还是我来决定。

这个边界很重要。

因为社交媒体不是越自动化越好。

尤其是 X 这种平台，如果完全交给 AI 去发，很容易变成没有人味的营销号。

所以我现在更倾向于让 Hermes 做前置筛选和草稿，而不是直接代替我表达。

第五，是 YouTube 频道运营和视频工作流。

我现在的 YouTube 频道方向主要是独立游戏开发分享。

不是单纯做 Unity 教程，而是聊更实际的东西：

怎么控制项目范围。

怎么做原型。

怎么上 Steam Demo。

怎么避开开发新手最容易踩的坑。

Hermes 在这里的作用，主要是帮我整理选题、写脚本、生成 SEO 包装、处理描述文案，以及辅助 YouTube 上传流程。

它已经接入了我本地的 YouTube 工作目录和 OAuth token。

所以对我来说，它不是一个单次生成标题的工具。

它更像是我频道运营里的一个后台助手。

我可以让它根据已有的内容方向，生成脚本结构、标题备选、简介、标签，甚至把内容和 Obsidian 里的旧笔记串起来。

第六，是本地项目和代码辅助。

Hermes 也能直接进入我的 Git 项目目录。

比如我现在有自己的 Unity 独立游戏项目，它可以帮我查看项目文件、整理需求、写开发计划、查 Git 状态，甚至在明确范围之后修改代码或文档。

这点和传统 AI 编程工具很像，但区别在于 Hermes 不只面对代码。

它可以同时理解我的笔记、我的内容计划、我的项目文件、我的自动化任务。

这就让它更像一个跨系统的工作助手，而不是单纯的代码补全工具。

## 第四，Hermes 真正改变的不是效率，而是工作方式

如果只说效率，Hermes 当然能提高效率。

比如写稿更快了，查资料更快了，整理邮件更快了。

但我觉得更重要的变化不是“快”。

而是我的工作方式变了。

以前我做一件事，经常要在很多软件之间来回切换。

Obsidian 里找资料。

浏览器里查信息。

终端里跑命令。

Telegram 里收消息。

邮箱里看通知。

X 上找互动机会。

YouTube 后台处理内容。

每一个工具都很有用，但它们彼此之间是断开的。

而 Hermes 的作用，就是在这些工具之间搭了一层 AI 操作层。

我可以用自然语言，把这些散在不同地方的动作串起来。

比如我说：

帮我根据最近的 Obsidian 稿子，写一篇 Hermes 介绍和使用方式的口播稿。

它就会先去读 Obsidian 里的旧稿子，理解我的写作风格，然后再根据它知道的本机部署情况，写成一篇新的稿件，最后保存回 Obsidian。

这个过程如果手动做，也不是做不了。

但你要自己打开文件，找参考，想结构，写初稿，保存，整理。

而现在，这些中间步骤可以交给 Agent。

我只需要提出目标，然后检查结果。

所以 Hermes 对我来说，真正有价值的地方，不是它帮我省了几分钟。

而是它让我开始把很多重复性的操作，重新设计成“可委托的任务”。

这其实是很重要的思维变化。

## 第五，使用 Hermes 的边界和问题

当然，Hermes 也不是没有问题。

我觉得如果你想部署类似的 AI Agent，有几个点一定要提前想清楚。

第一个是权限边界。

它能操作电脑，所以你必须知道哪些权限可以给，哪些权限不能给。

比如文件读写、终端命令、账号 token、社交媒体操作，这些都不是小事。

我现在的原则是：

能读的可以多一点，能写的要更谨慎。

能生成草稿可以放开，但真正对外发布的动作要有边界。

比如 YouTube 我可以让它辅助上传和包装，但我明确不让它删除视频。

X 我可以让它筛选互动候选和写回复草稿，但不是让它不经过判断就到处自动回复。

第二个是结果验证。

Agent 很强，但它不是完全可靠。

它可能误解你的意思，可能读错文件，可能生成不符合你风格的东西。

所以你不能把它当成一个百分百正确的员工。

更合理的方式，是把它当成一个执行力很强、但需要你验收的助手。

它可以帮你做第一版，帮你跑流程，帮你整理资料。

但关键判断还是要你自己来。

第三个是部署门槛。

Hermes 目前更适合愿意折腾的人。

你需要理解一点终端，理解配置文件，理解 API key，理解权限和服务。

如果你只是想找一个开箱即用的 AI 聊天工具，那它可能不是最适合你的。

但如果你愿意把它接入自己的真实工作流，那它的潜力就会非常大。

## 最后总结

OK，总结一下。

Hermes Agent 不是一个普通聊天机器人。

它更像是一个运行在你电脑里的 AI 工作系统。

它可以调用模型，也可以调用工具；可以在终端里执行命令，也可以读写本地文件；可以通过 Telegram 和你对话，也可以用定时任务主动帮你处理信息。

我的部署方式，是把它装在本地电脑上，配置好模型、工具权限、Telegram Gateway、Obsidian vault、Gmail、X、YouTube 这些工作流，然后让它长期在后台运行。

现在它对我来说，主要有几个作用：

第一，作为 Telegram 里的远程本地助手。

第二，辅助 Obsidian 内容创作和口播稿生成。

第三，定时整理 Gmail 未读邮件。

第四，筛选 X 上适合互动的内容并生成草稿。

第五，辅助 YouTube 频道的标题、描述、SEO 和上传流程。

第六，参与本地游戏项目和代码工作流。

我觉得这类工具未来真正有价值的地方，不是让 AI 写几段更漂亮的文案，而是让 AI 进入你的真实系统，理解你的文件、你的习惯、你的项目，然后帮你完成那些可以被委托的工作。

当然，它不会替代你做所有事情。

但它会逼你重新思考一件事：

我每天做的这些重复操作里，到底有多少是必须我亲自做的？

又有多少，其实可以变成一个清晰的任务，交给 Agent 去执行？

我觉得这才是 Hermes 最有意思的地方。
